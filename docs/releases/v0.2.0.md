# v0.2.0 - Generic Bridge Refactor

## Bridge

- Added `POST /v2/conversation` with a game-neutral envelope.
- Kept protocol v1 available for existing adapters.
- Removed the Stardew-only game restriction from the bridge core.
- Made world, relationship, and extended context optional.
- Added explicit `profileId` lookup and validated generic profile schemas.
- Added stable error codes and optional emotion/confidence response metadata.

## Persona handling

- Added a dedicated PersonaEngine with a clear immersion contract.
- Separated character voice from general knowledge and authoritative game state.
- Added structured Ollama output, local validation, one malformed-output retry, and a JSON-mode fallback for model/schema combinations that cannot compile the full grammar.
- Added disclosure and prompt-injection checks with an in-character fallback.
- Added a repeatable persona regression script covering normal, technical, hostile, and adversarial prompts.

`qwen2.5:1.5b` failed several regression cases. `qwen2.5:3b` was selected as the practical default for the test PC's 8 GB RAM. It improves instruction following and character voice without moving to an impractical 7B+ model.

## Stardew adapter

- Updated Adapter #1 to send protocol v2 envelopes.
- Added an explicit profile ID, stable player ID, nearby characters, and adapter metadata.
- Kept all Stardew state extraction inside the SMAPI mod.
- Added a waiting menu that keeps normal single-player play paused while the asynchronous request is running.
- Kept `Alt+0` as the conversation key.

## Verification

- Fourteen bridge tests pass.
- Release build succeeds against Stardew Valley 1.6.0 and SMAPI 4.0.6.
- Source and packaged bridge tests exercise the real Ollama API.
- Full player-controlled input/waiting/dialogue behavior still requires an in-save acceptance test.
